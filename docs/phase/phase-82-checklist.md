# Phase 82 Checklist

Status: PLANNED
Phase: [Phase 82](phase-82.md)
Consumer ledger: [CNCF Phase 104 checklist](../../../cloud-native-component-framework/docs/phase/phase-104-checklist.md)
Closure basis: 本台帳の実装・検証項目。計画文書の作成を製品機能の完了と扱わない。

## P82-01: 配布・信頼契約

- [ ] SHA sidecarの構文・取得規則・旧公開物の移行をspecに確定する。
- [ ] 外部署名形式・対応アルゴリズム・ライブラリと、未署名／署名取得失敗の区別を確定する。
- [ ] namespaceごとの署名権限、鍵情報形式、初期信頼鍵登録、更新・失効・有効期限を確定する。
- [ ] TUF採用範囲、旧鍵情報の再提示への扱いと、失効の既存キャッシュへの反映方針を記録する。
- [ ] 実際の取得キャッシュ経路・保存所有者・権限・同時取得と成功物の公開方法を確定する。

## P82-02: 公開物と鍵情報の配布

- [ ] 完成したCAR全体のSHA sidecarを公開用処理が生成できる。
- [ ] 同じCAR全体への任意の外部署名を生成・配布できる。
- [ ] namespaceと許可された提供者鍵の情報を、信頼の起点から検証できる形で配布できる。
- [ ] 鍵登録・更新・失効の運用例と、秘密鍵を配布物へ含めない手順を確認する。
- [ ] 通常の開発用CAR生成に公開用SHA・署名を要求しない。

## P82-03: 取得とキャッシュ登録

- [ ] 一時取得物のSHAを照合し、署名があれば許可された鍵で検証する。
- [ ] 未署名の正常CARを受け入れ、署名不正・取得障害から未署名へ切り替えない。
- [ ] 破損・検証失敗・I/O失敗の取得物を使用可能なキャッシュへ登録しない。
- [ ] 検証したそのCARを登録し、未検証の別取得物へ差し替えない。
- [ ] 登録後の保存管理、キャッシュ再利用と更新時の再取得検証が成立する。

## P82-04: ローディングとメタデータ

- [ ] 識別情報・runtime範囲・安全なパス・必要な実行ファイル・通常のI/O検証を維持する。
- [ ] CARローディング時の必須ABI存在・簡易検査を外し、実際の呼び出し元と仕様を整合させる。
- [ ] ABIメタデータの生成・公開・利用ツールの読み取りが成立する。
- [ ] `cozy lint abi`の前リリース比較を維持する。
- [ ] 正式キャッシュの通常ロードに全体SHA・署名の再検証や内部ファイル一覧照合を設けない。

## P82-05: 統合受け入れと運用

- [ ] 未署名／署名付き取得、破損、CARとSHAの同時改変、鍵差し替え、署名取得障害を実行仕様で確認する。
- [ ] 鍵情報の改竄・期限切れ・許可された鍵更新と、選定した失効方針を実行仕様で確認する。
- [ ] バイト列変更・SHA照合のProperty-Based Testingと、実際のキャッシュ往復を確認する。
- [ ] 公開用処理とCNCF取得処理を、選定したリポジトリfixtureで接続して確認する。
- [ ] 公開・鍵管理・キャッシュ再取得の運用手順を完成させる。
- [ ] 変更した各リポジトリの必要な検証・独立レビューと、実際の結果を記録する。
- [ ] 全受け入れ条件を台帳で確認し、未完了事項を明示してPhase閉鎖を判断する。
