# Document Projectの内部資料パッケージと外部作業領域

Date: 2026-11-11
Updated: 2026-11-16
Status: proposal / non-normative
Plan: [Phase 90](../phase/phase-90.md)

## 目的と利用例

案件フォルダのトップに完成物、source/に編集可能なDocument Projectを置き、配置後も同じ原稿から編集・生成・完成物更新を続けます。Dropbox同期フォルダで利用できるよう、生成中も一時ファイルを案件フォルダ内に作りません。Dropbox専用APIを必要としないローカルディレクトリ機能とします。

今回の利用例は `/Users/asami/Dropbox/@/1111.takumi/` です。

```text
1111.takumi/
├── simplemodeling-live-prototyping-ja.pdf
└── source/
    └── simplemodeling-live-prototyping.dox/
        ├── document-project.yaml
        ├── content/
        ├── images/
        ├── build/  # 永続的な生成設定のみ
        └── index.dox
```

Core、日英Document、統合index.dox、原図、スライドIR、動画台本、永続的な生成設定、必要な外部素材と選択した完成物を保持します。target/、実行ログ、キャッシュ、LaTeX中間物、バックアップ、一時的なstate/receipt/lockは同期領域に配置しません。内部資料という分類は公開先への自動登録を選択しない設定であり、ファイルのアクセス権を保証する機能ではありません。

## 現状の根拠

- [既存export仕様](../spec/document-project.md#phase-571-portable-export-bundle-contract)はarticle-review-htmlのみを公開用に出力し、Coreと原稿を含めません。
- 既存のCozyDocumentProjectLocalBuildとnative SmartDox/LaTeX生成を利用します。別のPDFレンダラーは作りません。
- 今回の日本語SmartDox原稿には元プロジェクトへの絶対画像参照があります。単なるディレクトリコピーでは移設後の独立した再生成を保証できません。

## 機能案

### 案件パッケージの配置

選択したDocument Projectの原稿依存関係と永続設定、指定した完成物を配置します。配置後のsource/を編集の正本とし、元のプロジェクトがなくても生成できます。初回はコピーとし、元原稿の削除や公開リポジトリからの除去は別の明示操作とします。既存の公開exportの選択規則は変更しません。

### 作業領域の分離

ProjectRoot、PackageRoot、WorkRootを区別します。ホストローカル設定または明示引数で同期対象外のWorkRootを選び、その配下のtarget/に実行ごとの作業領域を作ります。マシン固有の絶対WorkRootは持ち運ぶ原稿に埋め込みません。

実体パスでProjectRoot/PackageRootと作業領域の重複を検査します。Dropboxフォルダ名だけによる自動推測はしません。利用者が同期対象外の場所を指定でき、未設定時の既定値と優先順序を仕様化します。使用できない場合は案件内target/へフォールバックせず、設定診断を返します。

日英のLaTeX/PDF、infographic画像変換、スライドのレンダリング・組立て、音声合成、対話レンダリング、部分動画・最終結合、HTML・プレビュー・確認資料、ログ・プロセス状態を外部作業領域へ統一します。入力の隣に中間物を作るツールには、作業用入力を外部領域に用意します。既存の状態管理・provider経路が同期フォルダへ書く箇所も対象です。既存Work Artifact Placement Rulesには外部作業ルート配下のtarget/を使用して整合させ、必要な境界明確化は実装前に行います。

### Git管理対象との分離

Git管理するDocument Projectにも同じ作業領域の分離を適用します。原稿、Content Core、ロケール別Document、永続設定、必要な画像・図は管理対象に保ちます。作業用入力コピー、レンダリング中間物、ログ、キャッシュ、一時的な実行状態は外部WorkRootへ置き、Git対象外にします。通常はProjectとPackageのGit作業ツリー外を作業先とし、より大きなGit作業ツリーに含まれる場合は既知の作業ディレクトリだけをignoreする方針を定義します。

ignore設定の提供方法はP90-01で確定し、既存の利用者設定を保持します。PDF・画像などの拡張子を一括除外せず、完成物をGit管理するかはプロジェクトの方針で選択します。グローバルGit設定の変更や、追跡済みファイルの自動削除・追跡解除は行いません。既存中間物の移行は別途明示した範囲で扱います。`.gitignore`はGitの追加対象を制御するものであり、Dropbox対策は生成中も同期領域へ中間物を書かないことで実現します。

### 資源参照と再生成

原稿内は移設可能な資源参照を保ち、実行時に作業領域へ解決・materializeします。外部依存は組み込む資源と外部参照として保持するものを明示します。元の絶対パスを無条件に文字列置換する方式は採用しません。今回の画像は案件内へ取り込みます。リンク先の別文書は同梱または明示した参照として扱い、壊れた相対リンクを残しません。

### 完成物の更新

指定した生成対象が成功した後に完成物だけを所定位置へ反映します。単なる生成と配布先更新を分けて呼び出せるようにします。確認HTMLは外部作業領域で閲覧し、完成物として明示選択した場合のみ配置します。

配置設定にはProjectの相対位置、内部資料区分、選択製品・ロケール・完成物名、所有する出力先を記録します。保存場所・スキーマ・CLI名はP90-01で確定します。所有していない既存ファイルとの衝突は診断し、案件内の別資料は変更しません。生成失敗時は既存完成物を保持します。コピー失敗・中断時は部分出力の状態を明示し、成功と扱いません。同期領域内に一時ファイルを作れないため、別ファイルシステムをまたぐ置換の原子性は前提にせず、復旧方法を仕様化します。

ハッシュを承認条件や更新許可のゲートに使いません。原稿変更に応じて必要な生成を行い、完成物の配置履歴は外部作業領域に保持します。継続利用に必要な宣言的配置設定だけをsource/に保存します。

## 対象媒体と共通設定

日本語・英語それぞれの記事PDF、infographic、まとめスライド、音声、動画を今回のPhase 90の範囲とします。本文確認HTMLとCore確認HTMLも維持します。既存native producerを使い、画像→PDF→スライド、音声・対話映像→動画結合という実際の依存関係に沿って必要な工程を外部WorkRootで実行します。対象を選択しただけで未実装の自動執筆・producerが存在すると扱いません。

記事PDFは、統合index.doxにja/enのロケールを指定します。Core、各言語Document、編集可能な図・スライドIR・動画台本と設定は入力として保持します。音声を完成物として選択した場合は所定位置へ反映し、動画生成のための中間音声とは区別します。部分動画、レンダラーバンドル、LaTeX中間物、スライド組立て用データ等はWorkRootの作業資源です。拡張子だけで入力・完成物・中間物を判断しません。

共通toolchain・renderer・styleと記事固有の言語・素材・台本・レイアウト選択を分け、既存の設定層とnative設定契約で共通設定を集約します。SimpleModeling.orgで整理した共有コールバックは現状調査の入力とし、実装前に所有者と必要な接続を確認します。新たな代替レンダラーを作りません。共通設定の変更も再生成判定に含め、パッケージへの同梱または宣言した外部依存により、元checkoutへの絶対参照を不要にします。具体的な設定・CLI契約はP90-01でdesign/specへ定めます。

クラウドAPI、同期競合の自動マージ、公開・YouTubeアップロードは範囲外です。対応できない生成対象は明示し、同期フォルダ内生成へ迂回しません。

## 受入例

公開記事の[観測モデル](../../../simplemodeling-org/src/main/doxsite/development-process/observed-model.dox/README.md)と[知識ハーネス](../../../simplemodeling-org/src/main/doxsite/development-process/knowledge-harness.dox/README.md)をローカル受入例とします。両記事のja/en×PDF・infographic・スライド・音声・動画を隔離した作業コピーで生成し、原稿・台本・原図・永続設定の保持、全producerの外部WorkRoot利用、生成中の中間物ゼロを確認します。別パスへ移設し、元パスを参照できない状態でも再生成します。

既存のLive Prototyping内部資料は内部案件の配置・日本語PDF・確認HTMLの互換性を確かめる例として維持します。自動検証には匿名化した同等fixtureを使い、実資料一式をCozyの公開fixtureへ取り込みません。今回の計画更新では実際の媒体を生成しません。Phase実行時の受入でも、現行成果物と公開記録は保持し、自動公開や本番への上書きを行いません。

## 受入の重点

配置、編集、外部生成、完成物更新、再配置を一連で確認します。原稿の旧パスを利用できなくした状態でも、画像・図表を含む日英全媒体を生成できることを確認します。同期対象フォルダへの書き込みは前後比較だけでなく実行中の作成イベントも観測し、短時間で削除された中間物も検出します。失敗・中断・再試行、同名出力、別資料保持も対象です。現在の通常プロジェクト生成は互換性を保ちます。

Git管理fixtureでは正常・失敗・中断後の追加候補と追跡状態を調べ、中間物が混入せず、原稿・設定・必要な画像を追跡できることを確認します。完成物の管理方針と既存ignoreが保たれることも受入対象とします。
