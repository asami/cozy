# Document Projectの内部資料パッケージと外部作業領域

Date: 2026-11-11
Status: proposal / non-normative
Plan: [Phase 90](../phase/phase-90.md)

## 目的と利用例

案件フォルダのトップに完成物、source/に編集可能なDocument Projectを置き、配置後も同じ原稿から編集・生成・完成物更新を続けます。Dropbox同期フォルダで利用できるよう、生成中も一時ファイルを案件フォルダ内に作りません。Dropbox専用APIを必要としないローカルディレクトリ機能とします。

今回の利用例は `/Users/asami/Dropbox/@/1111.takumi/` です。

```text
1111.takumi/
├── simplemodeling-live-prototyping-ja.pdf
└── source/
    └── simplemodeling-live-prototyping.dox/
        ├── document-project.yaml
        ├── content/
        ├── images/
        ├── build/  # 永続的な生成設定のみ
        └── index.dox
```

原稿・図・設定・選択した完成物を保持します。target/、実行ログ、キャッシュ、LaTeX中間物、バックアップ、一時的なstate/receipt/lockは同期領域に配置しません。内部資料という分類は公開先への自動登録を選択しない設定であり、ファイルのアクセス権を保証する機能ではありません。

## 現状の根拠

- [既存export仕様](../spec/document-project.md#phase-571-portable-export-bundle-contract)はarticle-review-htmlのみを公開用に出力し、Coreと原稿を含めません。
- 既存のCozyDocumentProjectLocalBuildとnative SmartDox/LaTeX生成を利用します。別のPDFレンダラーは作りません。
- 今回の日本語SmartDox原稿には元プロジェクトへの絶対画像参照があります。単なるディレクトリコピーでは移設後の独立した再生成を保証できません。

## 機能案

### 案件パッケージの配置

選択したDocument Projectの原稿依存関係と永続設定、指定した完成物を配置します。配置後のsource/を編集の正本とし、元のプロジェクトがなくても生成できます。初回はコピーとし、元原稿の削除や公開リポジトリからの除去は別の明示操作とします。既存の公開exportの選択規則は変更しません。

### 作業領域の分離

ProjectRoot、PackageRoot、WorkRootを区別します。ホストローカル設定または明示引数で同期対象外のWorkRootを選び、その配下のtarget/に実行ごとの作業領域を作ります。マシン固有の絶対WorkRootは持ち運ぶ原稿に埋め込みません。

実体パスでProjectRoot/PackageRootと作業領域の重複を検査します。Dropboxフォルダ名だけによる自動推測はしません。利用者が同期対象外の場所を指定でき、未設定時の既定値と優先順序を仕様化します。使用できない場合は案件内target/へフォールバックせず、設定診断を返します。

LaTeX、画像変換、HTML、プレビュー、ログ、プロセス状態を外部作業領域へ統一します。入力の隣に中間物を作るツールには、作業用入力を外部領域に用意します。既存の状態管理・provider経路が同期フォルダへ書く箇所も対象です。既存Work Artifact Placement Rulesには外部作業ルート配下のtarget/を使用して整合させ、必要な境界明確化は実装前に行います。

### 資源参照と再生成

原稿内は移設可能な資源参照を保ち、実行時に作業領域へ解決・materializeします。外部依存は組み込む資源と外部参照として保持するものを明示します。元の絶対パスを無条件に文字列置換する方式は採用しません。今回の画像は案件内へ取り込みます。リンク先の別文書は同梱または明示した参照として扱い、壊れた相対リンクを残しません。

### 完成物の更新

指定した生成対象が成功した後に完成物だけを所定位置へ反映します。単なる生成と配布先更新を分けて呼び出せるようにします。確認HTMLは外部作業領域で閲覧し、完成物として明示選択した場合のみ配置します。

配置設定にはProjectの相対位置、内部資料区分、選択製品・ロケール・完成物名、所有する出力先を記録します。保存場所・スキーマ・CLI名はP90-01で確定します。所有していない既存ファイルとの衝突は診断し、案件内の別資料は変更しません。生成失敗時は既存完成物を保持します。コピー失敗・中断時は部分出力の状態を明示し、成功と扱いません。同期領域内に一時ファイルを作れないため、別ファイルシステムをまたぐ置換の原子性は前提にせず、復旧方法を仕様化します。

ハッシュを承認条件や更新許可のゲートに使いません。原稿変更に応じて必要な生成を行い、完成物の配置履歴は外部作業領域に保持します。継続利用に必要な宣言的配置設定だけをsource/に保存します。

## 初回の範囲

日本語PDF、本文確認HTML、Core確認HTMLを対象に、既存の生成経路へ外部WorkRootを通します。日英原稿と画像をパッケージで保持します。動画・音声・スライドの実行対応、クラウドAPI、同期競合の自動マージ、共有設定は後続候補です。未対応の生成対象は明示し、同期フォルダ内生成へ迂回しません。

## 受入の重点

配置、編集、外部生成、完成物更新、再配置を一連で確認します。原稿の旧パスを利用できなくした状態でも画像・図表・日本語PDFを生成できることを確認します。同期対象フォルダへの書き込みは前後比較だけでなく実行中の作成イベントも観測し、短時間で削除された中間物も検出します。失敗・中断・再試行、同名出力、別資料保持も対象です。現在の通常プロジェクト生成は互換性を保ちます。
