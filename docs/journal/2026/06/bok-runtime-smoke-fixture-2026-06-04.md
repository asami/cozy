published_at=2026-06-04

## Summary

BK-11/BK-15 runtime smoke validation was converted from the manual `/tmp/bok2`
exercise into a repeatable scripted fixture.

## Implementation

Added:

- `src/sbt-test/cozy/bok-runtime-smoke/build.sbt`
- `src/sbt-test/cozy/bok-runtime-smoke/test`
- `src/sbt-test/cozy/bok-runtime-smoke/check-bok-runtime-smoke.sh`

The fixture runs the public Cozy CLI through sbt:

```console
cozy bok create --save bok.d
cozy bok create-category architecture --project bok.d ...
cozy bok build bok.d --strategy wip --docker-image fake-antora:latest
```

The fixture installs local fake `dox` and `docker` commands at the front of
`PATH`. This keeps the smoke deterministic and avoids depending on external
Docker, Antora, or SmartDox executables while still exercising the Cozy runtime
command path.

## Dashboard Page Update

The BoK scaffold now treats the following pages as dashboard-style aggregate
pages instead of ordinary articles:

- Home
- Glossary
- History
- Manual
- Category top pages

Glossary, History, and Manual are exposed as BoK Console links. They are not
treated as ordinary category navigation items in the Home left navigation or
the top title bar. The top title bar keeps only Home and regular categories;
the right-side BoK Console owns Glossary, History, and Manual navigation.

Category top pages now include:

- article count
- term count
- total item count
- a compact bar chart for article/term distribution

`cozy bok build` writes category top HTML pages after the SmartDox/Antora
pipeline. This makes the dashboard cards and charts part of the final
`website.d/<category>/index.html` output, instead of relying on raw HTML passthrough
from SmartDox source conversion.

The default UI bundle embeds the `simplemodeling-org` Antora site assets plus
Cozy BoK dashboard CSS extensions.

## SmartDox Output Scope Alignment

`simplemodeling-org` uses SmartDox's `output.scope.policy=home_only` setting and
then composes separately generated HTML into the final site. Cozy now follows
the same operational model for BoK category dashboards:

- generated `site.conf` includes `output.scope.policy = home_only`
- `cozy bok build` invokes `dox site` with `-output.scope.policy home_only`
- category dashboard HTML is generated by Cozy after the SmartDox/Antora steps
- the policy can be overridden with `bok.output.scope.policy` when a project
  intentionally needs a different SmartDox output scope

## SmartDox Glossary Layout Alignment

SmartDox treats the top-level `glossary/` directory as the glossary collection
root. Category-specific terms should be placed under:

```text
src/main/doxsite/glossary/<category>/<term>.dox
```

Cozy no longer writes category terms to `<category>/glossary/<term>.dox`.
`cozy bok create-category --term glossary/<term>:...` remains accepted as an
input convenience, but the generated file is normalized to
`glossary/<category>/<term>.dox`.

The special Glossary dashboard page is generated into
`website.d/glossary/index.html` by `cozy bok build`. Cozy does not rely on
`src/main/doxsite/glossary/index.dox`, because that path overlaps SmartDox's
glossary collection root.

The Glossary dashboard now includes:

- glossary term count
- category group count
- active category group count
- links to Japanese and English glossary index pages
- the 10 most recently modified glossary terms

The Japanese and English glossary index links are backed by generated pages:

- `website.d/ja/glossary/index.html`
- `website.d/en/glossary/index.html`

These pages list the same SmartDox-owned glossary terms and link back to the
canonical generated glossary term pages under `website.d/glossary/<category>/`.
They are rendered as glossary index pages:

- Japanese index pages use kana sections and an `その他` bucket for terms whose
  reading cannot be derived from the current title-only metadata.
- English index pages use A-Z sections and an `Other` bucket.
- The top of each page renders an index navigation whose links jump to the
  corresponding section anchor.
- Terms whose title has no Japanese character are excluded from the Japanese
  index and remain visible in the English index.
- Glossary term source pages can define `reading=<kana>` in `# HEAD`.
  `yomi=<kana>` and `読み=<kana>` are also accepted as compatibility aliases.
- Japanese glossary index grouping uses `reading` first and falls back to the
  title when no reading metadata exists.
- `cozy bok create-category --term` accepts a fourth field:
  `path:title:definition:reading`.

Future page splitting can be added behind this section model once the number of
terms grows large enough to require multiple pages.

## SmartDox-owned Home Dashboard Metrics

Home dashboard totals and increment graphs should be produced from SmartDox
metadata, not by re-parsing `.dox` files in Cozy.

Reason:

- SmartDox already parses document metadata, glossary terms, notices, and
  history.
- Recomputing totals and time buckets in Cozy duplicates SmartDox logic.
- Keeping aggregation in SmartDox avoids drift between generated pages,
  glossary/history behavior, and Home dashboard numbers.

Expected SmartDox-side output:

- total category count
- total article count
- total glossary term count
- total item count
- item increment buckets
- automatically selected bucket scale: day, week, or month depending on the
  covered date span

Cozy should consume the SmartDox-produced dashboard metadata or generated Home
dashboard fragment instead of computing these values independently.

## SmartDox History Alignment

Cozy no longer treats `history/index.html` as the primary BoK Console History
target when SmartDox has generated year pages. During `cozy bok build`, the
BoK Console link resolves to the latest available SmartDox-generated
`history/<year>.html` page, falling back to `history/index.html` only when no
year page exists.

Generated seed documents now include `published_at=<yyyy-mm-dd>` in `# HEAD`.
This lets SmartDox collect articles and glossary terms into its generated
History pages.
