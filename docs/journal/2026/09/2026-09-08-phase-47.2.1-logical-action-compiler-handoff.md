## Accepted validation and composition contract

The generated compiler accepts consumer-supplied
`org.goldenport.cncf.unitofwork.ExecProgram[Unit]` bindings only. It rejects
unknown, duplicate, missing, and operation/input-incompatible bindings, plus
unknown or duplicate occurrence selections and selected occurrences that lack
required metadata. Accepted values are sequentially composed using the existing
Free/`UnitOfWorkOp` path in generated causal order: constituent `exit`,
`transition`, `entry`, followed by derived occurrences in declared order.

Each compiled occurrence retains definition and Action identity, operation and
input type, CML binding, source and causal provenance, ordinal, effect,
transaction, idempotency, and compensation metadata. It neither serializes an
executable program nor adds an Action algebra, provider handle, callback,
script, transaction/retry/recovery runtime, or Cozy CNCF runtime dependency.

## Consumer responsibility and development candidate

claimed, tested, or closed by Cozy.

a Cozy consumer-admission claim is prohibited as a workaround.
