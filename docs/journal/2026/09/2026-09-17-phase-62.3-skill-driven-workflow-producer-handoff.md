## Producer fixture contract

The fixture declares `WORKFLOW WorkflowProducer` at revision
`workflow-producer-v1`. Its ordered logical Actions are:

```text
BuildProject -> RunTests -> ReviewChange -> CommitChanges
```

`BuildProject`, `RunTests`, and `CommitChanges` are fixture-local completed
actions. `ReviewChange` is the sole `REQUIRED-OPERATION`, mapped to the typed
`WorkflowService.reviewChange` operation with:

```text
ReviewContext -> ReviewResult
```

The Required SPI identity is `review-change-capability`; the action identity is
`ReviewChange`. The source model retains the declared input/result types and
source provenance. `ReviewResult` extends `OperationResult`.

The executable specification proves the producer behavior through the
normalized Workflow and StateMachine API/SPI projection:

1. A Provider is selected only by the `StateMachineRequiredOperationIdentity`.
2. Provider execution returns one of `ActionExecution.Completed`,
   `ActionExecution.Suspended(Continuation)`, or `ActionExecution.Failed`.
3. A deterministic Provider completes `ReviewChange` and reaches
   `CommitChanges` and the terminal state.
4. An external suspending Provider completes the two preceding local actions,
   returns a durable `Continuation`, and does not advance past `ReviewChange`.
5. A matching typed `ContinuationResult` is accepted and resumes
   `ReviewChange`, then permits `CommitChanges` and terminal completion.
6. A stale `StateMachineRevision` or `ContextSnapshot` is rejected
   fail-closed, leaving the suspended run unchanged.

The binding boundary is therefore:

```text
StateMachine Required SPI
  -> Provider binding
  -> Provider execution
  -> ActionExecution
```

Provider binding is separate from participant or capability meaning. The
selected Provider determines whether execution completes, suspends with a
Continuation, or fails. A Continuation is an execution value returned by
`Suspended`, not a Workflow-wide execution mode or an Action/Participant
binding attribute.
