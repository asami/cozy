# Phase 58.1 Document and Summary Description DSL Decision

Date: 2026-09-12

## Trigger

The Phase 58 Article 9 overview and Step-slide HTMLs showed the recursive Step
tree, but review found that `Local Structure · sequence` and direct-child Flow
were difficult to distinguish. Inspection confirmed that the real acceptance
driver used only `sequence` and `next`, while the projection rendered nodes,
Relations, and Flow transitions with nearly identical generic styling.

Further review clarified that `format-ja.yaml` is not the desired authoring
authority. It combines localized semantic wording with HTML chrome and exists
primarily to feed one output projection. The actual requirement is a DSL that
defines the full document, plus a separate concise description at the level
needed by summary slides.

## Decision

Create **Phase 58.1: Document and Summary Description DSL Vertical Slice** as
a successor to completed Phase 58.

Phase 58.1 will preserve these distinct authorities:

1. `content/core.yaml` owns the locale-independent recursive logic tree;
2. `content/<locale>/document.yaml` owns the complete localized document
   organization and prose; and
3. `content/<locale>/summary.yaml` owns the deliberate concise selection used
   for summary-slide-level explanation.

The Document and Summary files are semantic authoring DSLs, not HTML, PDF,
PPTX, video, or infographic IRs. Output chrome and physical presentation
belong to Cozy locale resources, profiles, and renderers.

The Summary Description binds both the exact Core identity and the exact
Document Description identity. It is therefore reviewable as a deliberate
condensation rather than an unrelated second text or a silent automatic
truncation.

## Relationship to Phase 58

Phase 58 remains closed and historically correct as a recursive-Core vertical
slice. Its `format-ja.yaml` and HTML contracts are not rewritten in place.
Phase 58.1 establishes a new explicit route and does not add a permissive
compatibility reader or dual authority.

The new Article 9 acceptance driver must also correct the semantic weakness
exposed by the Phase 58 fixture. It must use multiple existing Logical
Patterns and typed Relations when warranted by the content, preserve the
difference between child-Step Flow and Step-local Structure, and make those
differences visible in human review. A pipeline test in which every
relationship is `next` is not sufficient acceptance evidence.

## First-slice outputs

The first slice produces:

- paired design and specification authority for both DSLs;
- strict typed loaders, identity binding, reference validation, and
  deterministic canonicalization;
- the real Article 9 Japanese `document.yaml` and `summary.yaml`;
- one deterministic document-review HTML; and
- one deterministic summary-review HTML.

## Deferred work

- Migration or retirement of Phase 46/46.1 or Phase 58 inputs and products.
- Updating every Document Project profile or scaffold.
- SmartDox article generation and site integration.
- Article PDF, summary-slide PDF, PPTX, video, infographic, publication,
  registration, deployment, upload, push, or external-service work.
- Automatic acceptance of AI-authored prose or summaries.
