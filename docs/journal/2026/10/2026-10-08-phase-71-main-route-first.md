# Phase 71 series: run the main route before expanding branches

Date: 2026-10-08 (Asia/Tokyo)
Status: planning update only; no product execution, acceptance or Goal transition.

## Decision and reason

The user requested a second optimization around a working main route first.
The 2026-10-07 plan grouped implementation and Specs but still deferred actual
native integration to 71.7. That could accumulate branches while leaving the
central generation/playback path unproven. This revision changes that order.
It supersedes blanket native-acceptance deferral, not aggregate full-suite deferral.

Known main-route failures are repaired in their owning Phase before expanding
branches or closing. An unavailable selected prerequisite remains open, with
its concrete missing condition; no file-open, decode-only result or listed
encoder is promoted to successful listening or hardware execution.

## Execution and evidence

Write the connected implementation and Executable Specifications together.
Use existing inputs/narration/assets and ordinary command logs, final media and
actual playback outcomes. Preserve relevant prior results; recheck only where
changes affect the result. Do not rerun accepted synthesis or review solely for
a Phase handoff. No new generic harness, bookkeeping service, comparison copy,
unchanged-input proof, per-helper or per-playback review is introduced.

Hand over working commands, input/settings references, actual outputs/results
and remaining cases through existing Phase records. Benchmark measurements
still require three warmed runs per supported case and separate cold startup;
earlier functional evidence does not substitute for actual timing.
