Status: P92-01 decision record; v1 design contract adopted, producer implementation and P93 presentation mapping pending, 2026-11-20

Phase 92 adopts the SmartDox v1 design contract as its producer-owned semantic baseline. This record connects it to the Phase 93 presentation extension; the companion [handoff specification](../spec/lexidox-knowledge-space-handoff.md) summarizes the contract and delivery gate. ## Joint contract lineage and release gate

LX-J01 requires one grammar and metadata lineage, LX-J02 identity resolution before presentation, LX-J03 independent concept classification, knowledge form and display role. LX-J04–J05 add source-language, translation and profile intent in Phase 93; LX-J06 preserves canonical knowledge and RDF, LX-J07 preserves legacy behavior and requires explicit version diagnostics, and LX-J08 shares authored fixtures and tests both routes. Phase 92 accepts the semantic baseline; Phase 93 adds a compatible presentation extension and separately accepts Core/Document and rendered output. Profile selection must never re-resolve a term or alter identity, canonical knowledge, target, or prose/code. Its precedence and missing-label behavior remain P93-01 decisions.

The adopted contract is SmartDox [design and implementation plan](https://github.com/asami/smartdox/blob/7207fa191cd32bd383684ca4b278ff402ddbc096/docs/design/lexidox-producer-baseline.md) and [v1 specification](https://github.com/asami/smartdox/blob/7207fa191cd32bd383684ca4b278ff402ddbc096/docs/spec/lexidox-knowledge-space.md), source revision `7207fa191cd32bd383684ca4b278ff402ddbc096`, received through the SmartDox owner. It adopts the conceptual proposal at `25a87f783a358556ed3ddf7d97cc43a41b5efafb` and separately pins the Cozy joint plan at `8b6c7588961bb09d8c90944d384b1f960d3cff9c`. The latter maps LX-J01–LX-J08; it does not turn the uncommitted additions to the conceptual proposal into committed text. The owner reports independent review and two existing suites (11 tests) for the document task; these do not demonstrate v1 implementation.

The producer plan implements parser/profile integration, then registry, resolution, diagnostics, interchange and RDF, then builds and verifies an identified artifact. P92-02 requires its actual coordinate, source revision, portable Japanese/English and legacy fixture inputs and outputs, and producer validation receipts. These have not been delivered. Cozy retains its existing admission and SIE boundaries and must not reconstruct missing output.

The v1 contract specifies `lexidox-knowledge/1` and the semantics summarized in the handoff. Phase 93 may add optional typed fields in the same lineage while preserving v1 identities and fields; incompatible semantics require a major version. P93-01 still must decide exact syntax, mapping, profile/entry/pattern precedence, missing-label behavior and version diagnostics, and record its alignment to this decision. The shared plan establishes identity resolution before label choice and the independence of classification, form and display role, but is not evidence that P93-01 has completed. Neither public output nor producer implementation is changed by this record.

## P92-01 and P93-01 requirements crosswalk

This comparison uses the P93-01 criteria in [Phase 93](../phase/phase-93.md) and its [checklist](../phase/phase-93-checklist.md), together with the joint plan pinned above. It records a common baseline for both Steps; it does not claim that P93-01 has been executed or accepted. Phase 92 cites this record and the SmartDox v1 revision for knowledge admission. P93-01 must cite the same record and revision when recording its accepted compatible extension, its own revisions and its delivery evidence.

| Joint requirement | P92 baseline and P93-01 responsibility |
| --- | --- |
| LX-J01, LX-J07: one lineage and compatibility | SmartDox v1 specifies the opt-in grammar, `simplemodeling-v1` profile and `lexidox-knowledge/1`; existing non-v1 behavior is retained. P93-01 specifies its optional typed extension, field reuse, version handling and diagnostics against this baseline; incompatible semantics require a major version. SmartDox owns the producer contract and implementation, Cozy consumes its delivered output. |
| LX-J02: identity before presentation | P92 resolves explicit reference Space, then document Space, then global scope and records Term, Concept, Space and page before label selection; ambiguous and undefined references do not retry. P93-01 binds labels and display to that resolved identity and target and specifies missing-label behavior without a new lookup. |
| LX-J03: distinct roles | `concept_type` is classification, `knowledge_form` selects section validation and a presentation role selects display. P93-01 maps ordinary term, named design pattern and code roles to styles; neither a display profile nor a Phase 91 explanation pattern changes the P92 knowledge form, classification or identity. |
| LX-J04–LX-J05: language and profiles | P93-01 defines source syntax and typed metadata for original definition language/name, localized labels, explicitly identified established translations, entry preferences and the three original-language, established-Japanese and Japanese profiles. It decides profile/entry/pattern precedence, missing language or labels and conflicting preferences without guessing language from spelling. These are not v1 fields already delivered by this decision. |
| LX-J06: knowledge and presentation | P92 specifies canonical sections, source/provenance and RDF/JSON-LD identities. P93-01 defines exact label/provenance reuse and a versioned Core/Document handoff for typed bindings, label intent, pattern emphasis and configured styles; HTML and LaTeX mappings preserve canonical definitions, relations, links and RDF. Fonts and colors remain configuration. |
| LX-J08: shared verification | SmartDox owns authored valid/invalid fixtures and producer validation. Cozy Phase 92 verifies actual knowledge admission and projection; Phase 93 extends the same semantic cases and verifies Core/Document and the three actual PDF/HTML selections and HTML switching. The built producer and fixtures remain a delivery gate, not evidence already received. |

SimpleModeling owns glossary meaning and public writing policy, SmartDox owns grammar, validation and serialization, and Cozy owns its admission, integration and output evidence.
