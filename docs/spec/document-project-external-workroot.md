# Document Project external WorkRoot specification

Status: Phase 90 target contract with a partially validated implementation; full acceptance remains open. Design and current-source evidence: [external WorkRoot design](../design/document-project-external-workroot.md). This contract applies to the new explicitly selected external-workspace route; existing [Document Project](document-project.md) behavior remains in force until its routes are adapted.

## Admission and configuration

A run MUST resolve WorkRoot in this order: explicit `--work-root`, host configuration `documentProject.workRoot`, then `${user.home}/.cozy/work` as local default. The value is host-local and MUST NOT be embedded as an absolute path in portable project configuration. Resolve physical paths by resolving existing components and symlinks to real paths, then appending normalized prospective components to the nearest existing real ancestor; reject ambiguous or unresolvable identities. The caller MUST identify every applicable synchronization root; do not infer synchronization from a directory name. Before any effects, reject equality or ancestor/descendant overlap in either direction between WorkRoot and each of ProjectRoot, PackageRoot and the identified synchronization roots. In particular, a synchronization root within `WorkRoot/target/document-project` is rejected because it would contain run artifacts. This separation holds during normal, failed and interrupted runs. Reject inaccessible, non-directory or unwritable paths before any effects; do not fall back. On a larger Git worktree, provide a narrowly scoped ignore entry for the exact work subtree only on explicit user request, preserving existing entries and tracked files. Never globally ignore extensions or change global Git configuration.

Portable declaration `source/cozy-package.yaml` contains schema `cozy.document-package.v1`, a source-relative project path, and ordered product/locale/destination entries. Locale is `ja` or `en`; product is `article-pdf`, `infographic`, `summary-slides`, `audio`, `video`, or an explicitly selected review product. Destinations are nonempty normalized relative paths below PackageRoot, outside `source/`. Reject duplicate product/locale entries, path traversal, symlink escapes and collisions with unowned files. Before any destination write, preflight all selected output file destinations by physical path, resolving existing and prospective components as above. Reject identical paths including aliases, ancestor/descendant pairs, and any existing parent whose shape conflicts with the required directory path. For example, `report` and `report/page.pdf` cannot both be selected output files. A failed preflight leaves all destinations untouched. An existing destination is owned only when recorded in the package declaration from initial placement or a previous explicit adoption; never infer ownership from its name. The declaration has no host WorkRoot, secrets, temporary state or publication credentials.

The implemented package CLI takes a placement declaration and explicit ordered product/locale pairs as shown below. Omitted selection does not mean every product. Local HTML build targets do not accept `--locale`; localized article review uses package refresh. Existing target identifiers and normal commands retain their established meaning. An explicit CLI WorkRoot takes precedence over host settings; package source never overrides it.

## Inputs, products and regeneration

Placement copies the required source closure to `source/`, including Core, both localized Documents, unified `index.dox`, authored figures, slide IR, scripts, persistent configuration and required assets. It preserves existing source and products and does not copy `target/`, caches, logs or transient state. Resolve external and absolute asset references by an explicit mapping to a package-relative copy or an explicitly declared external dependency. Missing, ambiguous or escaping references fail with a diagnostic; do not perform blind string replacement. Bundle permitted common styles and renderer assets or declare an independently installed toolchain; credentials and host paths remain host configuration. Relative references are resolved against their declaring file and materialized into each run without modifying the editable source.

Article PDF uses the same `index.dox` with explicit locale selection for ja and en. Common toolchain, renderer and style are shared configuration; locale, selected products, source and article-specific styling are project configuration. Project settings override common defaults only for declared article-specific fields; conflicting duplicate definitions in one layer are rejected. Regeneration decisions account for every declared direct and transitive source, common configuration, renderer/tool version and relevant locale/parameters. An unknown dependency or missing currentness evidence causes rebuild or a diagnostic, never an unsupported current claim. No approval hash gate is introduced.

Only explicitly selected successful candidates can be refreshed. Selected audio is a deliverable; speech chunks and video narration audio are intermediates. Reviews and confirmation HTML/images stay in WorkRoot unless explicitly selected. Each selected product has its own result; a failed product cannot replace its previous deliverable. Publication and cloud writes are separate operations outside this contract.

## Runtime, errors and recovery

Each run MUST allocate a unique owned subtree `WorkRoot/target/document-project/runs/<run-id>/`. Child cwd, input copies, temp environment, cache, provider artifacts, logs, state, receipts, preview output, LaTeX intermediates, renderer bundles, audio, part videos and assembly all resolve within that subtree. A provider that cannot honor the boundary MUST fail before execution. Successful and failed run work is retained until explicitly cleaned; cleanup is confined to a selected owned run subtree. Observing the boundary during execution, including short-lived files, is required in P90-02/P90-04.

Refresh first validates ownership and availability of all selected candidates. For each output it saves prior bytes and a progress record in WorkRoot, then copies to the owned destination without creating a package-local staging file. Cross-filesystem replacement and the whole batch are not atomic. Failure or interruption reports completed, uncertain and untouched outputs and leaves the external backup and candidate available. Recovery checks ownership and external changes, then either restores an uncertain output or retries it from the candidate; an unresolved conflict or restore failure is reported, never silently overwritten. Existing unselected products and unrelated files are preserved. No generation failure triggers refresh.

Existing intermediate files are not automatically deleted or migrated. A separate explicit selection must identify owned old paths and a destination or deletion action; handwritten inputs, current products, publication records, tracked files and ignore rules are preserved. The P90-04 acceptance must exercise normal, failed and interrupted generation and refresh, relocation without the original path, active-write monitoring, Git tracking, and both isolated real projects in ja/en for all five products. Full acceptance remains pending.

## Phase 90 implementation candidate

The candidate command `cozy document-project package place <project> --save <package> --declaration <yaml> [--work-root <path>] [--sync-root <path> ...]` consumes an explicit `cozy.document-package.v1` declaration. Its `project` is the source-relative destination project directory; `sources` lists project-relative files, including any explicitly authored files below `target`. `products` is an ordered array of `product`, `locale`, and package-relative `destination`. Optional `bundles` entries contain `from` (relative to the original project or absolute) and `to` (relative to package `source/`); their relative tree must include the callback's required configuration and assets. Optional `references` entries map exact media renderer-command and receipt-input paths from `from` to `to`, resolved relative to the placed project. Each mapped or unchanged renderer and receipt reference must name an explicitly copied file in `source/`. The input declaration can contain original host paths; the generated package declaration does not retain them. The caller must supply the complete transitive closure; only these parsed media references are rewritten.

`cozy document-project package refresh <package> --product <id> --locale <ja|en> [--product <id> --locale <ja|en> ...] [--work-root <path>] [--sync-root <path> ...]` generates ordered selections in separate children of one external run before any product update. The receipt and per-item `uncertain-N` and `completed-N` markers show progress; an item with neither marker is untouched. `cozy document-project package recover <package> --run <run-directory> [--work-root <path>]` restores touched outputs when their current bytes match the saved candidate or backup. Different bytes require manual reconciliation, including an interrupted partial copy whose bytes cannot be distinguished from an external edit. Initial placement stages the exact intended file bytes and destination plan in an external run before copying. The same recover command resumes that explicit placement run: it retains started destinations only when their bytes match the staged file, creates missing files, and refuses conflicting or incomplete bytes for manual reconciliation without deleting them.

The `article-review` and `core-review` selections use the configured `smartdox-article-html` and `document-structure-html` local-build targets respectively. Core review rejects a locale different from the configured Document input. Article review supplies the selected locale to SmartDox and requires an admitted language marker or matching project descriptor language. Slide review selects the generated summary montage; video review selects the deterministic storyboard projection for the matching project locale.

The package path and locale-selective article review have focused and partial native evidence. Complete transitive dependency discovery, automatic recovery of ambiguous partial writes, integration verification of slide and video review, remain to be established. Both relocated cases completed their 13 selected outputs using the independent host toolchain. The observed-model case used a role-compatible isolated Core copy because the original Core was rejected. Existing `.gitignore` is preserved; an explicitly declared authored asset under `target` still requires a suitable existing Git rule or an explicit user-managed exception to become trackable.


## Current command usage and toolchain boundary

Prepare a declaration with the complete selected authored closure and destination ownership before placement. Choose a WorkRoot outside the project, package and every identified sync root. Pass each applicable sync root explicitly. For example, with shell variables identifying existing paths:

```sh
cozy document-project package place "$PROJECT" --save "$PACKAGE" --declaration "$DECLARATION" --work-root "$WORK" --sync-root "$SYNC"
cozy document-project package refresh "$PACKAGE" --product infographic --locale ja --product infographic --locale en --product article-review --locale ja --product article-review --locale en --work-root "$WORK" --sync-root "$SYNC"
cozy document-project build "$PACKAGE/source/PROJECT_PATH" --target document-structure-html --work-root "$WORK" --sync-root "$SYNC"
cozy document-project package recover "$PACKAGE" --run "$RETAINED_RUN" --work-root "$WORK"
```

Replace `PROJECT_PATH` with the declaration's actual project path. Refresh requires each `--product` to be immediately followed by its `--locale`. Select only owned combinations. Other admitted products include `article-pdf`, `summary-slides`, `audio`, `video`, `core-review`, `slide-review` and `video-review`. The configured Core review locale must match its Document input. The local HTML targets also include `document-reader-html` and `smartdox-article-html`. Use the article-review selection for an explicit language. A direct media build uses `--target` and `--locale` with external WorkRoot. Inspect the command result and retained run receipt. A completed placement alone does not generate all products.

Keep portable article sources, assets and declared renderer inputs in the package closure. Treat independently installed Dox, renderer runtime and host provider settings as host dependencies. Keep credentials out of the package. The original site callback used in Phase 90 expects a relative `../smartdox` development checkout. It did not work from the copied package. A private test profile selected an independently installed `dox` on PATH and successfully rendered knowledge-harness PDFs, but this does not change or prove portability of the original callback. Provision and verify the renderer and its transitive dependencies for the actual host before relying on PDF or slides.

A failed preflight or generation does not authorize replacing previous products. Retain the external run on failure or interruption. Use `recover` only with the recorded run directory and its original package and WorkRoot. It resumes an admitted placement or restores touched refresh outputs when the recorded bytes establish ownership. If current destination bytes differ from the retained candidate or backup, or a partial copy is ambiguous, preserve the files and reconcile the conflict before retrying. The current evidence includes a real interruption before product copy, specification-level prepared-receipt recovery and native placement recovery of a deliberately withheld file. A real mid-copy interruption remains unverified.
